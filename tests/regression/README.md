# Регрессионная база — пункт 1 plan-0001

Этот каталог фиксирует **текущее** поведение CLI перед изменением detection/postprocessing.
Он не исправляет алгоритмы, ранжирование, координаты или CLI из пунктов 2–7.
План: [`docs/plans/plan-0001.md`](../../docs/plans/plan-0001.md).

## Запуск

Из корня проекта, Linux, Python 3.10+, GNU `/usr/bin/time`, обе штатные ONNX-модели:

```bash
cargo build --release
# Полная публичная регрессия, включая 6000×4000 и панораму 6000×800:
python3 tests/regression/run.py --include-slow
# Без двух больших сценариев:
python3 tests/regression/run.py
# Самопроверки harness, без моделей, Pillow и сети:
python3 -m unittest discover -s tests/regression -p 'test_*.py' -v
```

Модели при необходимости загружаются существующим `scripts/download_models.sh`.
Для самих тестов сеть, Pillow и установленные шрифты **не нужны**: fixtures уже сохранены.
Полный запуск занимает примерно минуту; текущему pipeline нужно около 1 GiB RSS.
У каждого процесса timeout 180 секунд (`--timeout`). Каждый случай запускает отдельный CLI
с `--threads 2`; загрузка моделей включена во время и пиковый RSS.

Дополнительные параметры: `--binary`, `--models-dir`, `--threads`, `--only ID ...`,
`--report target/regression-observed.json`. Файл отчёта не заменяет baseline.

### Baseline и целевой контракт — разные проверки

- `baseline.json` содержит фактический результат каждого публичного сценария: строки OCR,
  нормализованные строки, формат, основные выводимые поля, отдельные checksum, recovery,
  rotation/crop, polygon, exit code, время и RSS. Зафиксированы SHA-256 входов, моделей,
  бинарника, исходников и Cargo.lock, платформа и число потоков.
- `cases.json` содержит сценарии, размеры, хеши и **исходные** строки синтетических документов.
  Сравниваются не только checksum, но и данные: неверное имя может иметь все checksum OK.
- `known-failures.json` явно перечисляет существующие отклонения от целевого контракта.
  Они печатаются как `XFAIL`, а не как успешное распознавание. Даже для XFAIL изменения
  текущих строк, полей, checksum, exit code или геометрии дают ошибку baseline.
- Неизвестное нарушение контракта, изменение baseline, другой вход/модель или авария процесса
  приводят к ненулевому завершению runner. Ожидаемые улучшения также требуют ручной проверки
  и обновления baseline; автоматически «обучать» эталон на каждом запуске нельзя.
- `--strict-contracts` делает **все** нарушения, включая XFAIL, ошибками. Например:

  ```bash
  python3 tests/regression/run.py --strict-contracts --only white usage-no-argument
  # Сейчас завершается 1: оба дефекта действительно обнаруживаются.
  ```

Polygon сравнивается как неупорядоченный набор четырёх углов, с допуском
`max(3 px, 2% длинной стороны входа)`, симметрично в обе стороны. NaN/Inf запрещены.
Это ориентир локализации, а не требование побитового совпадения. Координаты пока относятся
к выбранному **oriented/cropped** кадру; переход к исходному файлу — пункт 4 плана.
Время и RSS сохраняются только для анализа, не являются кроссплатформенными assertions.
Runner не проверяет число recognition inference или внутренние аллокации: это последующие этапы.

## Зафиксированный контракт результата

| Условие | Кандидат | Код CLI |
|---|---|---:|
| Нет приемлемой MRZ-области ни в одной попытке | Нет | `1` |
| Правдоподобная область есть, OCR не разбирается | Да, исходные строки и ошибка разбора | `2` |
| MRZ разбирается, но хотя бы одна применимая checksum не прошла | Да, поля и результаты проверок | `2` |
| Все применимые checksum прошли | Да | `0` |
| Ошибка аргументов, загрузки модели или декодирования входа | Нет; диагностика ошибки, не MRZ | `1` |

`--help`/`--version` — успешные информационные команды, код `0`, без кандидата.
Неприменимые проверки — `N/A`, а не неудачные checksum. Checksum-valid не означает подлинность
документа и не гарантирует правильность имени. Checksum-guided recovery не меняет код `0`,
если все применимые проверки успешны; флаг recovery сохраняется в baseline.

Приемлемость области **не определяется успешностью `mrz::parse`**: иначе исчезнет законный
сценарий кода `2`. Два отдельных fixture (`parse-failed`, `checksum-failed`) сохраняют этот
контракт через полный detection → recognition → parser → CLI pipeline.

Это нормативный контракт, не утверждение, что текущая реализация уже полностью ему отвечает.
Сейчас однотонные изображения и обычная фотография создают ложных кандидатов с кодом `2`,
а clap также использует `2` для usage errors. Они отдельно отмечены как известные дефекты,
подлежащие исправлению в пунктах 2 и 5 соответственно.

и целевые данные, и фактический OCR. Поэтому будущая оптимизация не сможет незаметно
ухудшить даже уже частично распознаваемый пример.

## Обновление и воспроизводимость fixtures

Все синтетические данные вымышлены: страна UTO, фамилия TESTER, документ SPECIMEN.
Генератор независимо рассчитывает контрольные цифры (веса 7/3/1), задаёт длины строк
30/36/44 и сохраняет исходные строки в manifest. Негативные примеры не используют
личные паспортные фотографии.

Для **перегенерации**, не обычного запуска, использовались Python 3.12, Pillow 12.2.0,
FreeType 2.14.3 и Ubuntu Mono Regular variable (`UbuntuMono[wght].ttf`) из Ubuntu Font Family,
Canonical, [Ubuntu Font Licence](https://design.ubuntu.com/font/). Сам шрифт не включён;
его путь и точный SHA-256 проверяются в `generate.py`. Иная версия рендера может изменить
байты PNG: сравните результат вручную, не обновляйте manifest и baseline вслепую.

```bash
python3 tests/regression/generate.py
# Только после проверки diff и осознанного принятия нового эталона:
python3 tests/regression/run.py --record --include-slow
# Приватный эталон — отдельно, остаётся в files/:
python3 tests/regression/run.py --record --private
```

`--record` запрещает частичную перезапись публичного набора. По умолчанию тест никогда
не меняет baseline. Проверка ошибок и источников остаётся обязанностью ревьюера.
