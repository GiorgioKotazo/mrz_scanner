# Пункт 2: ограниченный detection и проверка области

## Реализация

- Detection input — непосредственно 256×256. Билинейный sampler читает виртуальный
  квадрат с чёрным padding, не создавая RGB-квадрат размера длинной стороны исходника.
  Сохранены half-pixel mapping OpenCV INTER_LINEAR, BGR, NCHW и `/255`.
- `Letterbox` хранит исходные oriented-размеры, размер виртуального квадрата и offsets.
  При нечётной разнице лишний пиксель находится справа/снизу. Старый `pad_to_square` удалён.
- Heatmap перед Otsu имеет сторону `min(max(width, height), 1536)`.
  Binary, contours и min-area rectangle работают только в этой ограниченной системе.
  Polygon математически возвращается в oriented-изображение; перевод из rotation/crop
  в исходный файл не входит в пункт 2.
- Native 256×256 был проверен: TD1 потерял checksum-valid результат. Лимит 1024 также
  проверен: регрессия на `large`. При 1536 сохраняются все ранее успешные сценарии.
  Поэтому ограниченный resize → threshold сохранён вместо неэквивалентного threshold
  в native heatmap. Размер 1536 — лимит, а не дополнительный полноразмерный буфер.
- До recognition проверяются confidence, ненулевая площадь контура, конечные координаты,
  стороны rectangle (минимум 3 и 8 пикселей в системе 256×256), площадь минимум 32/65536
  detection-кадра и широкий aspect ratio 1.2–30. Эти условия применяются совместно.
- Warp отклоняет вырожденную/неприменимую геометрию: стороны менее 2 исходных пикселей,
  площадь менее 4, сторону больше диагонали исходника, центр вне изображения,
  NaN/Inf, невозможность построить perspective transform. Размеры больше не принудительно
  округляются до 1×1. Recognition вызывается только после успешных проверок и warp.
- Неразобранные кандидаты имеют одинаковый score: сохраняется первый правдоподобный,
  а не самый длинный OCR. Ранжирование разобранных MRZ и условия ранней остановки не менялись.

## Калибровка confidence

До добавления порога весь публичный набор запускался с `--debug-dir`.
Из PNG heatmap после ограниченного resize измерен максимум в каждой выполненной попытке
(full/crop, 0/90/180/270, до штатной ранней остановки). Значения ниже — uint8 / 255;
модели и входы закреплены хешами в `baseline.json` / `cases.json`.

| Входы | Наблюдавшийся peak |
|---|---:|
| white | 1–16 / 255 |
| black | 2 / 255 |
| solid | 1–14 / 255 |
| photo | 7–24 / 255 |
| DOCSAID, успешная full/0 | 192 / 255 |
| TD1/TD2/TD3/MRV, их повороты, odd-size, tiny | 253–255 / 255 |
| checksum-failed / parse-failed | 253–255 / 255 |
| center-crop, включая успешный crop | 251–255 / 255 |
| stretched, full (неверифицированный OCR) | 250–254 / 255 |
| stretched, crop (обрезанная MRZ) | 9–18 / 255 |
| large | 255 / 255 |
| panorama, full | 2–188 / 255 |
| panorama, crop (неверифицированный OCR) | 253–254 / 255 |

Принят консервативный минимум peak **51/255 (0.2)**: выше максимума отрицательных
примеров с запасом, заметно ниже минимумов читаемых положительных попыток.
Это предварительная калибровка на данном наборе, не гарантия для любых документов:
новые низкоконтрастные/необычные данные требуют дополнительной проверки. Confidence
не заменяет геометрию и не требует успешного `mrz::parse`.

Для повторного измерения используйте `--debug-dir target/calibration/<case>` для каждого
публичного fixture и прочитайте максимум `heatmap-*.png` (например, Pillow `getextrema()`).
Debug-файлы локальных паспортов нельзя сохранять как публичные fixtures.

## Регрессии и принятые изменения baseline

Публичный baseline обновлён только после сравнения с исходным и ручного разбора отличий:

- Все 13 ранее успешных публичных сценариев остались успешными.
- DOCSAID и три локальных изображения совпадают с **исходным** baseline по OCR, данным
  и checksum; polygon в прежнем допуске. Приватный baseline не перезаписан.
- TD2, TD3 и повороты TD3: изменились только неоднозначные raw OCR `O/0`, `I/1` после
  исправления нечётного padding; нормализованные строки, поля и checksum прежние.
- `checksum-failed`: raw OCR изменился, но поля, checksum-failure и код `2` сохранены.
- `parse-failed`: изменились сырые неразбираемые строки; правдоподобный кандидат и код `2`
  сохранены. Фильтрации по успешности parser нет.
- `stretched` и `panorama`: изменился ранее мусорный OCR, но не поля/checksum/код/категория
  результата; остаются XFAIL, а не объявляются успешными.
- `tiny` и `odd-size`: результаты исходного baseline сохранены, прежние XFAIL остались.
- white, black, solid, photo: вместо ложного кандидата возвращается код `1`, без OCR.
  Эти четыре сценария удалены из `known-failures.json`.
- Три usage-error XFAIL не менялись: это пункт 5.

Итог полного повторного запуска: **17 PASS, 7 XFAIL, 0 неожиданных ошибок**.
Отдельный Rust model-тест проверяет 608×448 и перспективно искажённый синтетический TD3
(данные и checksum), допустимые parse/checksum failures и **0 recognition inference**
на всех поворотах full/crop четырёх отрицательных fixtures.

## Память

Для 6000×4000 detection RGB — 256×256, heatmap и binary — максимум 1536×1536,
а не 6000×6000. В памяти остаются декодированное изображение, существующие копии/повороты,
warp и ONNX Runtime: их оптимизация не входит в эту задачу.
Unit-тест проверяет лимит для метаданных 6000×4000 и 60000×800; sampler также проверяется
на узкой панораме без создания большого квадратного RGB.

Один сравнительный прогон на той же машине, release, 2 потока, Peak RSS (KiB):

| Сценарий | До (пункт 1) | После |
|---|---:|---:|
| large, 6000×4000 | 988800 | 888104 |
| panorama, 6000×800 | 925972 | 827296 |
| DOCSAID | 803872 | 761628 |
| white | 770228 | 220464 |
| photo | 760616 | 219176 |

Это ориентиры, не жёсткие межплатформенные assertions; повторные замеры могут отличаться.

## Проверка

```bash
cargo fmt --all -- --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo test --release -- --ignored --test-threads=1
cargo build --release
python3 tests/regression/run.py --include-slow
python3 tests/regression/run.py --strict-contracts --only white black solid photo
python3 tests/regression/run.py --private
python3 -m unittest discover -s tests/regression -p 'test_*.py' -v
```

Приватный запуск требует уже существующие файлы из `files/`. Тесты без моделей:
13 Rust-тестов и 9 Python-тестов. Отдельно — 1 model-тест (по умолчанию ignored).
